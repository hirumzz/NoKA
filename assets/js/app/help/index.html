Gateway Navigation & Menu Guide

Dashboard

Displays real-time status of your active Kong connection (Postgres health, configuration synchronicity, node details) along with visual charts tracking requests/second, top-hit endpoints, and slowest paths.

Services Click for Full Tutorial

Allows you to manage upstream APIs or microservices. A service object represents your backend API, defining the upstream URL, protocol, and connection timeouts where Kong will forward matched requests.

Routes Click for Full Tutorial

Defines how incoming client requests map to your services. A Route matches criteria (like path prefixes, methods, or headers) and forwards the request to its parent service.

Consumers

Represents a client or consumer of your API. Used to attach authentication credentials (like API keys, JWT, Basic Auth) and apply granular rate limiting or Access Control List (ACL) grouping rules per client.

Plugins

Middleware modules that run during request execution. Plugins handle cross-cutting concerns like security, traffic throttling, log forwarding, and header transforms. They can be applied globally, or scoped to specific services/routes.

 Upstreams

Virtual hostnames used for load balancing. Add multiple targets (IP:port) behind an upstream to distribute traffic. Kong handles health checks and failover automatically.

Vaults, Keys & Key Sets (Kong 3.x+)

Configure backend vault adapters (like HashiCorp Vault, AWS Secrets Manager) to securely store system secrets. Keys and Key Sets manage cryptographic identities (like JWK, public keys) used for token verification.

Common Mistakes

  • Forgetting to press Enter on path input — After typing a path like /my-api, you MUST press Enter to confirm it. If you just type and click Submit, the path won't be saved.
  • No routing rule defined — A Route requires at least one matching criteria (path, host, method, or header). Without it, Kong rejects the Route.
  • Wrong Service host — The host must be resolvable from Kong's network. Use container names in Docker (e.g. my-backend), not localhost.
  • Path without leading slash — Paths must start with /. Writing api/v1 instead of /api/v1 will fail.
  • Forgetting to select a Kong connection — Before managing anything, ensure you have selected an active Kong node in the Connections menu.

Quick Start (3 Steps)

  1. Create a Service — Point it to your backend (e.g. http://my-api:3000).
  2. Add a Route — Define a path like /my-api and press Enter to confirm.
  3. Test it — Call http://kong-host:8000/my-api and see your traffic forwarded.

Services — Full Tutorial

What is a Service?

A Service in Kong represents your actual backend application or microservice. It tells Kong where to forward incoming requests that match associated Routes. Think of it as a pointer to your upstream API.

Step-by-Step: Creating a Service
  1. Go to Services in the left sidebar menu.
  2. Click the "+ Add Service" button (top-right).
  3. Fill in the Name — a friendly identifier (e.g. user-service).
  4. Set the Protocol — usually http or https.
  5. Set the Host — this is the hostname of your backend. In Docker, use the container name (e.g. my-backend-app). For external APIs, use the domain (e.g. api.example.com).
  6. Set the Port — the port your backend listens on (e.g. 3000, 8080).
  7. Optionally set Path — a base path that gets prepended to the request path (e.g. /v1).
  8. Click Submit.

Common Mistakes with Services
  • Using localhost as host — Inside Docker, localhost refers to the Kong container itself, NOT your host machine. Use the Docker service name or the host's IP address instead.
  • Wrong port number — Make sure the port matches what your backend is actually listening on, not the Docker published port.
  • Including path in host field — The host should be ONLY the hostname. Don't put my-api.com/v1 in host. Put /v1 in the Path field separately.
  • Using https without valid certificate — If your backend uses a self-signed cert, Kong may reject the connection. Use http for internal services.
  • Forgetting the service has no Routes — A Service without Routes won't receive any traffic. You must create at least one Route.
Example: Proxy to a Node.js backend
Name: my-node-app
Protocol: http
Host: node-backend (Docker container name)
Port: 3000
Path: (leave empty)

→ Kong will forward requests to http://node-backend:3000

Routes — Full Tutorial

What is a Route?

A Route defines rules that match client requests and forwards them to a Service. Routes are always attached to a Service. You can have multiple Routes pointing to the same Service (e.g. different paths or domains all going to the same backend).

Step-by-Step: Creating a Route
  1. Go to Services → click on the Service you want to add a Route to.
  2. Click the "Routes" tab, then click "+ Add Route".
  3. Optionally set a Name for easy identification.
  4. Add at least ONE matching rule:
    • Paths — Type the path (e.g. /my-api) and PRESS ENTER to add it.
    • Hosts — Type a domain and press Enter (e.g. api.mysite.com).
    • Methods — Select HTTP methods (GET, POST, etc.).
    • Headers — Type header rules and press Enter.
  5. Set Protocols — usually http, https.
  6. Decide on Strip Path — if ON, the matched path prefix is removed before forwarding.
  7. Click Submit.
CRITICAL: You Must Press Enter!

The most common mistake when creating Routes: After typing a path like /my-api in the Paths input field, you MUST press the Enter key on your keyboard to confirm the value. The path appears as a tag/chip when confirmed.

If you just type the path and click Submit without pressing Enter, the path will NOT be included and Kong will reject the Route with: "at least one of hosts, paths, methods, or headers must be set"

Common Mistakes with Routes
  • Not pressing Enter after typing a path — This is the #1 mistake. The input uses a "chip" system. You MUST press Enter for the value to register.
  • Path without leading / — Always start paths with a forward slash. api/v1 is invalid, use /api/v1.
  • No matching criteria at all — Kong requires at least one of: paths, hosts, methods, or headers. You can't submit an empty Route.
  • Conflicting Routes — Two Routes with the same path but different services can cause unexpected behavior. Use regex_priority to control which wins.
  • Strip Path confusion — When Strip Path is ON and your backend expects the full path (e.g. /api/v1/users), the backend will only receive /v1/users if the Route path is /api. Turn it OFF if your backend needs the complete URL.
  • Using trailing slash inconsistently — /api and /api/ are treated differently by Kong. Be consistent.
Example: Route for a user microservice
Name: users-route
Paths: /api/users (remember to press Enter!)
Methods: GET, POST, PUT, DELETE
Protocols: http, https
Strip Path: ON

→ Client calls: GET http://kong:8000/api/users/123
→ Backend receives: GET http://user-service:3000/123
(because /api/users is stripped)
